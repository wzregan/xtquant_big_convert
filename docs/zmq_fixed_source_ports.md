# 本机网络桥接的客户端源端口池

某些大 QMT 环境会检查当前进程所有 TCP 连接的对端地址。RPC 服务监听端口与客户端源端口是不同的：只配置 `50060/50061` 两个服务端口，不能保证客户端从允许的源端口发起连接。

`zmq.client_source_ports` 是可选设置。未配置时保留系统分配源端口的原有行为；配置后，RPC 的每个调用线程以及每个推送订阅通道都从该列表独占一个端口。端口池不足、端口被其他程序占用或建连失败时明确报错，不会退回随机源端口。

```python
BIGQMT_REDIS_CONFIG = {
    "transport": "zmq",
    "redis_enabled": False,
    "zmq": {
        "connect_address": "tcp://127.0.0.1:50060",
        "quote_push_connect_address": "tcp://127.0.0.1:50061",
        "redis_discovery_enabled": False,
        "client_source_ports": [
            50050, 50052, 50053, 50054, 50055, 50056, 50057, 50058,
            50059, 50062, 50063, 50064, 50065, 50066, 50067, 50068,
            50069, 50070,
        ],
        "client_source_lock_dir": "C:/ProgramData/qmt-grpc/source-port-locks",
        "client_source_connect_timeout_seconds": 1.0,
    },
}
```

以上示例保留外部 gRPC 的 `50051` 以及 QMT 的 `50060/50061` 监听端口，提供 18 个客户端源端口。只有启用该功能时才创建租约目录，且仅支持明确的 `tcp://127.0.0.1:端口` 目标。不要同时在目标地址中手工拼接另一个源地址。

所有使用同一端口池的本机客户端进程必须共用同一 `client_source_lock_dir`，并具有该目录的读写权限。文件锁覆盖套接字生命周期；正常停止、线程退出回收和进程被终止后均释放锁，不需要删除租约文件。库外程序仍可占用这些端口，因此每次建连还会检查 ZeroMQ 的实际 TCP 建连事件，并尝试池中的其他端口。

源端口设置只管理本库客户端的连接。它不改变 QMT 的网络规则，也不处理 QMT 内部线程自己使用的连接。QMT 的业务监听地址、交易接口权限、账户配置及交易门禁都不受此选项影响。

客户端停止前应先等待在途 RPC 完成。推送套接字及其租约由订阅线程自行关闭，避免在 Windows 上跨线程关闭正在轮询的 ZeroMQ 套接字。可用并发连接数受端口池大小限制，需要将 RPC 线程、行情心跳、推送通道及其他客户端进程一起计入容量。
