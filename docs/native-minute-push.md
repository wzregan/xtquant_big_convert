# 原生分钟推送桥接

大 QMT 只执行原生订阅、退订和回调转发。行情缓存、订阅去重、历史合并、缺口校验及补齐由 qmt-grpc 负责。

## 接口

- `ping.sdk_capabilities` 在当前 ContextInfo 提供原生订阅及退订方法时包含 `native_minute_push_v1`。
- `xtdata.native_minute_push` 为普通布尔属性，`connect()` 握手后更新；读取属性不执行 RPC。
- `subscribe_quote(code, period="1m", count=0, callback=...)` 在没有历史起止参数且握手确认能力时使用原生 `ContextInfo.subscribe_quote(code, "1m", "none", "list", callback)`。非零 count 或历史起止参数保留原有轮询行为，参数原样传给取数接口；新调用宜使用独立批量读取接口获取历史。
- `subscribe_quote_many(codes, period="1m", callback=..., timeout_seconds=None)` 返回证券到本地订阅句柄的映射。一次 SDK 调用最多 256 只，失败释放本次申请的所有句柄；回滚失败的服务端句柄由租约清理继续回收。
- `unsubscribe_quote(handle)` 释放单项；`unsubscribe_quote_many(handles)` 仅批退订给定的原生分钟句柄，未选订阅保持有效，Tick 继续使用已有清理路径。
- 历史读取仍保持 `get_market_data_ex(..., subscribe=False)`，不会隐式产生订阅。

Tick 和其他周期保持现有路径。旧桥接握手没有原生能力时，单只 1m 保留原有轮询且 `native_minute_push` 为 False；新增原生批订阅入口明确抛出 `NotImplementedError`，qmt-grpc 对明确 False 的后端选择旧单只入口。握手失败或已确认能力后的原生订阅失败直接传播，不降级为轮询。

## 调度与资源边界

创建分钟订阅默认每 8 只发出一个控制 RPC，每批完成后让出 QMT 调度。193 只因此是 25 个订阅控制请求，**193 只行情批量读取仍可以是一个请求**。通过 `BIGQMT_MINUTE_SUBSCRIBE_BATCH_SIZE` 配置每批 1～32 只；服务端每批最多接受 32 项。

所有订阅控制批共用 `timeout_seconds` 总预算，省略时使用客户端 RPC 超时配置。每批将剩余秒数同时传给 RPC 等待和服务端循环。原生 C++ 单次调用无法抢占，只能在其返回后停止后续调用并回滚，因此需要盘中实测单次创建耗时；不能把请求分批等同于每批必然在固定毫秒数内返回。

续租和批退订每批最多 256 项，不为每只证券创建心跳线程。服务端按客户端和订阅编号保存原生句柄及租约，回调只复制进入队列，由唯一发送线程转发。队列默认最多 4096 条、32 MiB，慢消费者不会无限增加内存。

## 缺口与代次

每个原生句柄拥有独立代次和递增序号。客户端在重复数据、乱序、换代及消息缺失时保留明确行为：重复或旧代次消息丢弃，缺口先交付 `{code: {"__gap": True}}`。队列溢出、快照失败和发送失败也产生缺口通知。

该标记不表示已经完成补齐。qmt-grpc 必须失效对应缓存的完整性证明并重新同步，不能依靠墙上时间把未完成分钟当作已完成分钟。

## 验收边界

离线回归覆盖真实服务端注册表、RPC 处理器、客户端会话和 SDK 转换，包含 193 只短批控制、共享预算、部分失败回滚、租约失效、晚到回调、溢出、重连代次及大整数精度。

上线前仍须在实际大 QMT 盘中验证原生分钟回调格式、到达延迟、订阅额度、单次原生创建耗时，以及共享策略线程上账户/交易请求的延迟。历史批量读取结果不代替这些实时验收。
